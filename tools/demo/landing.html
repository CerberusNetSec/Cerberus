What Cerberus does

Point your devices' syslog at it. Cerberus parses each vendor's logs, looks for attacks and behaviour that is out of the ordinary, and raises an alert that says why it matters and what to do. It is free, self-hosted and needs no agents on your devices. Version {{version}}, Apache 2.0.

24 detectors

Port scans, host sweeps, brute force and password spraying, a login that succeeds after failures, lateral movement, beaconing to a command-and-control server, large transfers, services exposed to the internet, risky outbound connections, admin logins from new places, and passwords or keys sent in clear text.

Mapped to MITRE ATT&CK

Every detection names its tactic and technique. A matrix page shows where your alerts fall, and which tactics network logs cannot see.

Guidance with every alert

Why it matters and the steps to take, written for the team that runs the firewalls. Repeats fold into one alert; false positives are marked once, with a reason, and stay quiet.

High Risk Ports

Traffic and findings on RDP, SMB, Telnet, FTP, databases and the other services attackers go for first: what is open to the internet, what is allowed out, what is in clear text.

Topology from SNMP

Polls your devices (read-only, LLDP and CDP) and draws the network they describe, with alert counts on each device.

Notifications

Email, Telegram, Pushbullet, signed webhooks, or any HTTP API with your own template, for ticketing, chat and SOAR tools.

AI agents and an API

A built-in MCP server lets Claude and other agents read and triage alerts with a scoped token. The same token works on the HTTP API.

Accounts, SSO and an audit log

Viewer, analyst and admin roles; single sign-on with any OpenID Connect provider; every sign-in and change recorded.

One instance, or scaled out

A single instance handles a few hundred devices. For thousands: collectors, detection workers, standby processors, Kafka, PostgreSQL and ClickHouse, with a Helm chart.

Devices it understands

Connectors for these are built in. Anything else that sends RFC 3164 or RFC 5424 syslog works through the generic connector, and a connector is a short YAML file you can write yourself.

  • OPNsense
  • Palo Alto Networks (PA-series, PAN-OS)
  • Fortinet FortiGate
  • Cisco IOS and IOS-XE switches and routers
  • Cisco ASA and Firepower
  • Juniper SRX and Junos
  • Ubiquiti UniFi and EdgeOS
  • Aruba AOS-CX, AOS-S and mobility controllers
  • Dell OS9, OS10 and N-series; Brocade and Ruckus ICX
  • RTL-Playground switches
  • Linux hosts: OpenSSH, PAM and netfilter logs

Quick start

You need Docker. This runs one instance; see the deployment guide for Kubernetes, Helm and several sites.

git clone https://github.com/CerberusNetSec/Cerberus.git
cd Cerberus
docker compose up -d --build
docker logs cerberus        # prints the generated dashboard password once

Open http://<host>:8080, then send your devices' syslog to port 514 on the host. To see alerts before touching a real device: python tools/simulate.py.
